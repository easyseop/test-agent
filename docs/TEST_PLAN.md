# 테스트 계획

> 사람이 읽는 테스트 목적과 합격 기준을 기록합니다.  
> 실제 자동 실행 정의는 `configs/<사이트>.yaml`, 실행 결과는 `runs/`에 남깁니다.

## 역할

| 담당 | 책임 |
|---|---|
| 사용자·업무 담당자 | 정상 기준과 위험 동작 승인 |
| Codex·Claude | 화면 조사와 YAML 작성 |
| Runner | 반복 실행과 판정 |
| 개발자 | 확인된 버그 수정 |

## 테스트 목록

| ID | 테스트 | 합격 기준 | 정답 근거 | 위험 |
|---|---|---|---|---|
| DEMO-001 | 전체 주문 조회 | 화면 건수와 DB 건수가 같음 | 시드 DB | 조회 전용 |
| DEMO-002 | 상태 필터 | 선택한 상태의 주문만 표시 | 시드 DB | 조회 전용 |

## 운영 규칙

- 배포 전, 관련 코드 변경 후, 정기 점검 때 다시 실행합니다.
- 합격 기준이 바뀌면 업무 담당자 승인 후 문서와 YAML을 함께 수정합니다.
- 자동 탐색은 저장·삭제·결제·발송을 실행하지 않습니다. 쓰기 테스트는 시드·스테이징에서만 명시적으로 승인합니다.
- LLM 위키는 테스트가 많아진 뒤 검색용으로 추가하며 정답 기준으로 사용하지 않습니다.
